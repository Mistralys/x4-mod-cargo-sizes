# WP-002: Create Class-Range Backend Service and Endpoint

## Overview

Create a new backend service that iterates all ships of a given type, computes physics adjustments for each using the current slider configuration, and returns aggregated min/max/median ranges. Expose this via a new REST endpoint.

## Plan Reference

**Plan Steps:** 10–16 (Phase 2)

## Description

The class-range feature answers the critical modding question: "will any ship become unplayable?" by computing physics impacts across all ships of a type (transport, mining, auxiliary, carrier) for a given configuration. The service iterates all matching ships, applies the physics calculator to each, and aggregates results into min/max/median ranges. It also identifies the worst-case and best-case ships by name.

## Requirements

### Step 10: Create `ClassRangeRequest` DTO
- File: `gui/backend/src/DTOs/ClassRangeRequest.php`
- Fields:
  - `shipType: string` (transport, mining, auxiliary, carrier)
  - `cargoMultiplier: float`
  - `dragReductionTiers: array`
  - `jerkReductionTiers: array`
  - `inertiaImpactFactor: float`
  - `useEffectiveRatioCap: bool`
  - `dragReductionFactor: float`
  - `accelerationResponsiveness: float`
  - `engineId: ?string` (optional — for engine-dependent metrics)
- Include `fromArray()` static factory method.

### Step 11: Create `RangeMetric` DTO
- File: `gui/backend/src/DTOs/RangeMetric.php`
- Fields: `min: float`, `max: float`, `median: float`, `unit: string`, `label: string`
- Include `toArray()` serializer.

### Step 12: Create `ShipMetricSummary` DTO
- File: `gui/backend/src/DTOs/ShipMetricSummary.php`
- Fields: `shipId: string`, `shipName: string`, `size: string`, `massRatio: float`, `topSpeed: ?array{original: float, adjusted: float}`, `acceleration: ?array{original: float, adjusted: float}`, `dragChangePercent: float`
- Include `toArray()` serializer.

### Step 13: Create `ClassRangeResponse` DTO
- File: `gui/backend/src/DTOs/ClassRangeResponse.php`
- Fields: `shipCount: int`, `metrics: array` (RangeMetric objects for topSpeed, acceleration, dragChange, inertiaChange, jerkChange, massRatio), `worstCase: ShipMetricSummary`, `bestCase: ShipMetricSummary`
- Include `toArray()` serializer.

### Step 14: Create `ClassRangeService`
- File: `gui/backend/src/Services/ClassRangeService.php`
- Constructor dependency: `ShipDataService`
- Main method: `calculateClassRange(ClassRangeRequest $request): ClassRangeResponse`
- Internal logic: iterate all ships of requested type from `ShipDefs`, for each:
  a. Create `PhysicsCalculator` with real mass + cargo data
  b. Find applicable drag/jerk tiers for the given multiplier
  c. Compute drag/inertia/jerk adjustments using real per-ship values
  d. If engine selected: compute top speed = `(thrustForward * engineCount * 1000) / dragForward`
  e. If engine selected: compute acceleration = `(thrustForward * engineCount * 1000) / adjustedFullMass`
  f. Collect per-ship results
- After iteration: compute min/max/median for each metric
- Identify worst-case (highest mass ratio) and best-case (lowest mass ratio) ships
- Private helper: `computeMedian(array $values): float`

### Step 15: Create `ClassRangeEndpoint`
- File: `gui/backend/src/API/Endpoints/ClassRangeEndpoint.php`
- Method: `calculate()` handling `POST /api/calculate/class-range`
- Parse request body → `ClassRangeRequest::fromArray()`
- Call `ClassRangeService::calculateClassRange()`
- Return JSON response.

### Step 16: Register the New Route
- Modify: `gui/backend/src/API/Router.php`
- Add: `$app->post('/api/calculate/class-range', [$classRangeEndpoint, 'calculate']);`

## Technical Constraints

- **Synchronous file I/O only**.
- **PHP strict types** — `declare(strict_types=1)` in all new files.
- **Readonly DTOs** — all new DTO properties must be `readonly`.
- **PSR-12 coding standard**.
- **Performance target**: <100ms backend computation for ~80 ships.
- **No new dependencies**.
- Uses existing parent mod classes: `PhysicsCalculator`, `AdjustedDrag`, `AdjustedInertia`, `AdjustedJerk`, `ReductionTier`.

## Acceptance Criteria

1. `POST /api/calculate/class-range` accepts a `ClassRangeRequest` JSON body and returns a valid `ClassRangeResponse`.
2. Response includes min/max/median `RangeMetric` objects for: massRatio, dragChange, inertiaChange, jerkChange, and (when engine selected) topSpeed and acceleration.
3. Response identifies worst-case ship (highest mass ratio) and best-case ship (lowest mass ratio) with their metrics.
4. Ships with `getCargoCapacity() == 0` are handled without division-by-zero errors.
5. Engine-dependent metrics (topSpeed, acceleration) are null/omitted when no `engineId` is provided.
6. Backend endpoint responds in <100ms for the full ship class iteration.
7. All new DTOs have `readonly` properties and `declare(strict_types=1)`.
8. Route is registered in `Router.php`.
9. No new Composer dependencies added.

## Risks & Mitigations

| Risk | Mitigation |
|------|------------|
| Class-range for large ship classes exceeds 100ms | Pre-tested: ~80 ships × ~10 ops = ~800 ops is <10ms in PHP |
| Ships with zero cargo cause division-by-zero | Guard against zero cargo in per-ship calculation |
| Worst-case ship is always a niche ship | Intended behavior — range bars show distribution context |
