# WP-004: Frontend Display Components

## Overview

Create the reusable UI components for visualizing class-wide range data: `RangeBar` for horizontal min—median—max visualization, `AbsoluteMetricCard` for single absolute metric display, `WorstCaseCard` for worst/best case ship identification, and `ClassRangePanel` as the container component. Update `ResultsPanel` to include the new panel.

## Plan Reference

**Plan Steps:** 23–27 (Phase 5)

## Description

These components provide the visual layer for the class-range feature. The `RangeBar` is a reusable pure-CSS/Tailwind horizontal bar. The `AbsoluteMetricCard` shows original→adjusted comparisons for absolute values. The `WorstCaseCard` identifies the edge-case ships. The `ClassRangePanel` orchestrates them all. Finally, `ResultsPanel` is updated to render the new panel below existing results.

## Requirements

### Step 23: Create `RangeBar` Component
- File: `gui/frontend/src/components/UI/RangeBar.tsx`
- Reusable horizontal bar showing min—median—max with labeled markers.
- Props: `min: number`, `max: number`, `median: number`, `unit: string`, `label: string`, `highlightValue?: number` (optional — highlight selected ship's value within range).
- Render as horizontal div with positioned markers (pure CSS/Tailwind, no chart library).
- Display absolute values at min/max endpoints and median marker.

### Step 24: Create `AbsoluteMetricCard` Component
- File: `gui/frontend/src/components/ResultsPanel/AbsoluteMetricCard.tsx`
- Displays a single absolute metric with original → adjusted comparison.
- Props: `label: string`, `originalValue: number`, `adjustedValue: number`, `unit: string`, `contextPhrase?: string`
- Shows delta: "+15.2%" or "−8.3%".
- Context phrase displayed as subtitle text.

### Step 25: Create `WorstCaseCard` Component
- File: `gui/frontend/src/components/ResultsPanel/WorstCaseCard.tsx`
- Displays worst-case and best-case ship identification.
- Props: `worstCase: ShipMetricSummary`, `bestCase: ShipMetricSummary`, `engineSelected: boolean`
- Shows ship name, size, mass ratio, and if engine selected: top speed original → adjusted.
- Visual emphasis on worst case (warning color) vs best case (success color).

### Step 26: Create `ClassRangePanel` Component
- File: `gui/frontend/src/components/ResultsPanel/ClassRangePanel.tsx`
- Container combining `RangeBar` instances + `WorstCaseCard`.
- Props: `data: ClassRangeResponse | null`, `loading: boolean`, `error: string | null`, `engineSelected: boolean`
- States:
  - Loading: show skeleton/spinner
  - No data: "Select a ship type and adjust settings to see class-wide impact"
  - Data: render all sub-components
- Renders:
  - Section header: "Class Impact: {shipCount} {shipType} ships at {multiplier}x"
  - `RangeBar` for mass ratio (always shown)
  - `RangeBar` for drag change % (always shown)
  - `RangeBar` for inertia change % (always shown)
  - `RangeBar` for jerk change % (always shown)
  - If engine selected: `RangeBar` for top speed (m/s), acceleration (m/s²)
  - `WorstCaseCard` for worst/best case ships

### Step 27: Update `ResultsPanel.tsx`
- Accept new optional `classRangeData` and class-range loading/error props.
- Render `ClassRangePanel` below existing result sections.

## Technical Constraints

- **TypeScript strict mode** — all components must pass `strict: true`.
- **No chart library** — `RangeBar` uses pure CSS/Tailwind positioned markers.
- **No new npm dependencies** — use existing packages only.
- **TailwindCSS v4** — use Tailwind utility classes for styling.
- Follow existing UI component patterns (see `Card`, `Spinner` from `gui/frontend/src/components/UI/`).

## Acceptance Criteria

1. `RangeBar` renders a horizontal bar with correct min/median/max marker positioning for various value distributions.
2. `AbsoluteMetricCard` displays original → adjusted values with delta percentage and optional context phrase.
3. `WorstCaseCard` shows worst-case (warning color) and best-case (success color) ships with name, size, mass ratio, and top speed when engine is selected.
4. `ClassRangePanel` correctly handles loading, empty, and data states.
5. `ClassRangePanel` renders range bars for all metrics (mass ratio, drag, inertia, jerk changes always; top speed and acceleration only when engine selected).
6. `ResultsPanel` renders `ClassRangePanel` below existing results.
7. Engine-dependent range bars only appear when engine is selected; clear message shown when no engine selected.
8. All components compile under TypeScript strict mode.
9. No new npm dependencies added.
