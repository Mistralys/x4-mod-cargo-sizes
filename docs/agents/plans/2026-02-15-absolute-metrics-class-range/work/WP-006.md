# WP-006: Frontend Wiring and Integration

## Overview

Wire all new components, hooks, and API calls together in `App.tsx`. Connect the `useClassRange` hook, build `ClassRangeRequest` objects from the current configuration, pass `shipId` to the physics calculation, and pass class-range results down to `ResultsPanel`.

## Plan Reference

**Plan Steps:** 28–30 (Phase 6)

## Description

This is the integration work package that connects all the individual frontend pieces. The class-range calculation fires alongside (but independently from) the single-ship calculation when the user adjusts sliders. The `App.tsx` component manages the state flow, ensuring both calculation paths receive the correct configuration data.

## Requirements

### Step 28: Update `App.tsx`
- Import and use the `useClassRange` hook.
- Add state for the selected ship type (needed for class-range API; may already be available in `ShipSelector` callbacks).
- In the calculation trigger effect, also fire the class-range calculation alongside the single-ship calculation.
- Build a `ClassRangeRequest` from the current config + selected ship type + multiplier.
- Pass class-range results (`data`, `loading`, `error`) down to `ResultsPanel`.

### Step 29: Update `handleShipDetailsChange` Callback
- In `App.tsx`, ensure the callback also captures the ship type for the class-range request.

### Step 30: Add `shipId` to Physics Calculation
- In `App.tsx`, add a `shipId` field to the `PhysicsConfig` request constructed in `triggerCalculation`.
- This enables the backend (WP-001) to load real per-ship physics data.

## Technical Constraints

- **TypeScript strict mode** — must compile under `strict: true`.
- **No new npm dependencies**.
- Two parallel API calls per slider change (single-ship + class-range) must not cause racing — separate hooks with independent state, class-range uses longer debounce (500ms vs 300ms).
- Follow existing state management patterns in `App.tsx`.

## Acceptance Criteria

1. `App.tsx` uses the `useClassRange` hook and passes results to `ResultsPanel`.
2. Class-range calculation fires when sliders change, using the currently selected ship type.
3. `shipId` is included in the physics calculation request to enable real per-ship data lookup.
4. Both single-ship and class-range calculations run independently without race conditions.
5. Class-range uses 500ms debounce; single-ship remains at 300ms.
6. `ClassRangePanel` appears in the right panel below existing single-ship results and updates reactively.
7. Total user feedback (debounce + API + render) is <600ms.
8. All modified files compile under TypeScript strict mode.
9. No new npm dependencies added.
